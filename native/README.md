# Demo Shop native tests (WebdriverIO + Appium)

The third part of the workshop: testing a **native mobile app** on the iOS simulator and the
Android emulator, the way `lvuk-native-apps/e2e` tests our brand apps. Same stack: WebdriverIO 9,
Appium 3 (XCUITest + UiAutomator2), Mocha, TypeScript, screen objects and tags.

```
native/
  app/   the Demo Shop as a React Native (Expo) app, talking to ../backend
  e2e/   the tests
```

The app is a tiny version of what you tested in Parts 1 and 2: login, a product list with search
and categories, a cart (swipe to remove), orders that go from PENDING to CONFIRMED or REJECTED,
and a contact form with native controls. Every element has a `testID`.

## Setup (once)

You need a Mac for iOS. Android also works on Linux and Windows.

| Tool | Version | Why |
| --- | --- | --- |
| Node.js | 24 or newer | runs WebdriverIO and Appium |
| Xcode | 26.2 (26.1 and 26.3 also work) | iOS simulator, builds the app |
| iOS simulator runtime | iOS 26.1, **Universal** variant | `xcodebuild -downloadPlatform iOS -buildVersion 26.1 -architectureVariant universal` |
| CocoaPods | 1.16 or newer | iOS dependencies of the app (`brew install cocoapods`) |
| Android SDK | platform 36, emulator, platform-tools | Android Studio, or `brew install --cask android-commandlinetools` |
| An Android emulator | Pixel 9, API 36 (Android 16) | Device Manager in Android Studio, or `avdmanager` |
| JDK | 17 | builds the Android app (`JAVA_HOME=<jdk 17> npm run build:android`) |
| JDK | 21 | the backend (`mvn spring-boot:run`), as in Part 2 |

Add this to `~/.zshrc` and open a new terminal:

```bash
export APPIUM_HOME="$HOME/.appium"
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$ANDROID_HOME/cmdline-tools/latest/bin:$PATH"
```

Install the dependencies and the **pinned** Appium drivers (same versions as `lvuk-native-apps`):

```bash
cd native/app && npm install
cd ../e2e && npm install
npx appium driver install appium-xcuitest-driver@11.17.6 --source=npm       # iOS
npx appium driver install appium-uiautomator2-driver@8.1.0 --source=npm     # Android
npx appium driver list --installed   # should list xcuitest@11.17.6 and uiautomator2@8.1.0
```

> Never run an unpinned `appium driver install xcuitest`: it pulls the newest driver, which may
> need a newer Appium than ours (3.5.2) and fails. To reinstall, uninstall first, then use the
> pinned command.

### Build the app (once, and after you change it)

The tests install the app from `e2e/app/`. The build scripts create a **Release** build (the
JavaScript is bundled inside, so no Metro server is needed) and copy it there:

```bash
cd native/app
npm run build:ios       # -> e2e/app/ios/DemoShop.app   (~5 min the first time)
npm run build:android   # -> e2e/app/android/demo-shop.apk (~5 min the first time)
```

The builds are git-ignored. `app/ios` and `app/android` are generated by Expo; never edit them
by hand, change `app.json` instead.

> The tests use `noReset`, so Appium keeps the installed app between runs. After rebuilding,
> uninstall the old one so the new build gets installed:
> `xcrun simctl uninstall booted com.example.demoshop` or `adb uninstall com.example.demoshop`.

## Running tests

Three things must be running first:

```bash
# 1. the backend (http://localhost:8080), JDK 21
cd backend && mvn spring-boot:run

# 2. a device
xcrun simctl boot "iPhone 17" && open -a Simulator      # iOS
emulator -avd Pixel_9_API_36                            # Android

# 3. the tests (WebdriverIO starts Appium for you)
cd native/e2e
npm run test:ios        # or: npm run test:android
```

| Command (in `native/e2e`) | What it does |
| --- | --- |
| `npm run test:ios` / `npm run test:android` | All lessons (exercises are skipped) |
| `npm run test:ios -- --spec ./tests/specs/03-gestures.spec.ts` | One lesson |
| `npm run test:ios -- --mochaOpts.grep @smoke` | Only tests tagged `@smoke` |
| `npm run test:ios:exercises` | The exercises |
| `npm run test:ios:solutions` | The trainer's solutions |
| `IOS_DEVICE="iPhone 17 Pro" IOS_VERSION=26.3 npm run test:ios` | Another simulator |
| `npm run typecheck` | TypeScript check |

The **first iOS run** builds WebDriverAgent (Appium's helper app on the simulator) and can take a
few minutes before the first test starts. Later runs reuse it.

On a failure you get the error in the terminal, a screenshot in `e2e/logs/FAILED-*.png`, and
Appium's full log in `e2e/logs/wdio-appium.log`.

## The app

| Screen | What is there | Deep link |
| --- | --- | --- |
| Login | `qa@example.com` / `password123`, show/hide password, errors from the backend | |
| Shop | Product list that loads slowly (~1.2 s), search, category chips, cart badge, a toast | `demoshop://shop` |
| Cart | Quantities, total, **swipe left to remove**, "+1", "Empty cart" (native alert), Place order | `demoshop://cart` |
| Order | Status polls from PENDING to CONFIRMED or REJECTED | |
| Contact | Text inputs, segmented topic, radio buttons, a native **Switch**, field errors | `demoshop://contact` |

Test-only deep link: `demoshop://session/<token>?to=cart` makes the app use a session created
through the API (lesson 7). A real app would ship it in test builds only, like the backend's
`/api/test` endpoints.

The app talks to the backend at `localhost:8080` (iOS) or `10.0.2.2:8080` (Android: the
emulator's name for your Mac). Logging out or restarting the app ends the session.

## Things that differ between iOS and Android

| | iOS (XCUITest) | Android (UiAutomator2) |
| --- | --- | --- |
| `testID` becomes | accessibility identifier: `~my-id` | resource-id: `//*[@resource-id="my-id"]` |
| Elements below the fold | exist, with `visible="false"` | do not exist until you scroll to them |
| Text of a button / label | `label` attribute | `text`, or `content-desc` for an accessibility label |
| A switch is on when | `value` is `"1"` | `checked` is `"true"` |
| Back | no system back; use the app's button | `driver.back()` |
| Keyboard | not every keyboard has a "hide" key; tap outside | `driver.hideKeyboard()` |
| `addValue("x")` | types at the end of the text | **replaces** the text, like `setValue` |
| Native alert (`Alert.alert`) | `driver.getAlertText()` works; find buttons inside `XCUIElementTypeAlert` | `getAlertText()` says "no alert" (React Native uses its own title id); read the dialog's elements, buttons are in CAPITALS |
| Waiting for idle | | before every command the driver waits until the app is idle; a spinner never is, so `wdio.android.conf.ts` turns that wait off (`waitForIdleTimeout: 0`) |
| Waiting for something to go away | `waitForDisplayed({ reverse: true })` on an element found earlier can keep saying "displayed"; use `expect($(...)).not.toBeDisplayed()` or `waitUntilGone()` | works either way |
| Big container views | often report `visible="false"` even on screen; wait for a real element inside | report correctly |
| An `accessibilityLabel` | **replaces** the visible text you read with `getText()` | goes to `content-desc`; `text` is unchanged |

Keep these in helpers and screen objects (`driver.isIOS` / `driver.isAndroid`), not in tests.

## Appium Inspector

To see the element tree, the testIDs and the attributes:

1. Install [Appium Inspector](https://github.com/appium/appium-inspector/releases).
2. Start Appium: `cd native/e2e && npm run inspector` (keep it running).
3. In Inspector, connect to `127.0.0.1:4723` with these capabilities (iOS shown):
   ```json
   {
     "platformName": "iOS",
     "appium:automationName": "XCUITest",
     "appium:deviceName": "iPhone 17",
     "appium:platformVersion": "26.1",
     "appium:bundleId": "com.example.demoshop",
     "appium:noReset": true
   }
   ```
   For Android: `"platformName": "Android"`, `"appium:automationName": "UiAutomator2"`,
   `"appium:appPackage": "com.example.demoshop"`, `"appium:appActivity": ".MainActivity"`.

Stop the Inspector session before running tests: both use port 4723.

## Suggested session plan (~2h)

1. **How a native test runs** (15 min): the Appium session, capabilities, why the app has
   `testID`s. Open Appium Inspector on the login screen.
2. **Lessons 01 to 03** (30 min): run each on iOS, then on Android. Spend time on the
   keyboard and on scrolling: they are where native tests differ most from web tests.
3. **Lesson 04** (15 min): timing. Make a test fail by asserting "CONFIRMED" without `wait`.
4. **Lesson 05** (15 min): read the platform table above, then the switch and alert tests.
5. **Lessons 06 and 07** (20 min): deep links and API setup make native suites fast.
6. **Lesson 08 + exercises** (25 min+): pairs work on `99-exercises.spec.ts`, on both platforms.

## Troubleshooting

- **`"DemoShop" Needs to Be Updated` / app does not install on iOS:** the simulator runtime is the
  arm64-only variant. Check `xcrun simctl runtime list -j` (`supportedArchitectures` must include
  `x86_64`) and download the Universal one (Setup table).
- **First iOS run times out creating the session:** WebDriverAgent is being built. Run again, or build it
  once: `xcodebuild -project "$APPIUM_HOME/node_modules/appium-xcuitest-driver/node_modules/appium-webdriveragent/WebDriverAgent.xcodeproj" -scheme WebDriverAgentRunner -destination 'platform=iOS Simulator,name=iPhone 17,OS=26.1' build-for-testing`
- **`Could not find a driver for automationName`:** `APPIUM_HOME` is not set, or the drivers are not
  installed. See Setup.
- **"Cannot reach the shop. Is the backend running?" in the app:** start the backend. On Android
  the app uses `10.0.2.2:8080`; on iOS `localhost:8080`.
- **A test sees an old version of the app:** uninstall it (see "Build the app").
